## Build & Run Commands

```bash
# Build (from repo root)
dotnet build NoteApp.slnx

# Run (from repo root)
dotnet run --project src/NoteApp

# EF Core migrations (from src/NoteApp)
cd src/NoteApp
dotnet ef migrations add MigrationName
dotnet ef database update

# User secrets (from src/NoteApp)
cd src/NoteApp
dotnet user-secrets set "ConnectionStrings:NoteDb" "Server=YOUR_SERVER;Database=noteDb;User Id=YOUR_USER;Password=YOUR_PASSWORD;TrustServerCertificate=True"
```

```bash
# Publish the single self-contained exe (~95 MB; NoteApp.csproj sets IncludeAllContentForSelfExtract — DacFx
# needs real assembly paths — and EnableCompressionInSingleFile). Output: bin/Release/net10.0-windows/win-x64/publish/
dotnet publish src/NoteApp/NoteApp.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

```bash
# Tests (from repo root) — NoteApp.Tests: xUnit on the pure layers (Domain, mapper, encryption, preview, view models); no DB, no UI thread.
# NoteApp.UiTests: the real WPF views (NoteEditorView...) off-screen on one shared STA dispatcher (tests/NoteApp.UiTests/Wpf.cs),
# view models on repositories that throw — still no DB. Wrap each test body in Wpf.Run(...), drive typing with OpenEditor.Type.
dotnet test NoteApp.slnx
```

Three exporters are wired from the editor header: PDF (`Services/PdfExportService.cs`, QuestPDF), Word (`Services/Export/WordExportService.cs`, Open XML SDK v3) and Markdown (`Services/Export/MarkdownExportService.cs`, CommonMark; images go to a `<name>_files` folder beside the `.md`, underline as `<u>`, lettered lists come out numbered) — every block in note order, links as hyperlinks, files by name. All three render from the WPF-free `DocElement` model in `Services/Export/DocumentModel.cs`, produced on the UI thread by `Services/Export/RichTextDocument.cs` (FlowDocument → elements). When the editor gains a formatting feature, extend the model and the extraction once, then each renderer (all three); `WordExportService.Render` is unit-tested by reading the `.docx` back with the SDK; `PdfExportService.Render` (stream out) is smoke-tested the same way.

## Architecture

WPF desktop app (.NET 10) with functional programming patterns (Zoran Horvat style). SQL Server backend via EF Core 10. Solution file is `NoteApp.slnx` (not `.sln`).

### Layer Dependency Flow

```
Domain (pure, zero dependencies)
  -> Data (EF Core entities, configurations, repositories)
    -> Services (orchestration, mapping, encryption)
      -> ViewModels (CommunityToolkit.Mvvm)
        -> Views (WPF XAML + MaterialDesignInXAML)
```

DI is configured in `App.xaml.cs`. Connection string loaded via .NET User Secrets (key: `ConnectionStrings:NoteDb`), overridable by `NOTEAPP_`-prefixed environment variables and command-line arguments (`NOTEAPP_ConnectionStrings__NoteDb`, `NOTEAPP_DataFolder`); the design-time `NoteDbContextFactory` reads the same variables, so `dotnet ef database update` follows them. An overridden connection string puts "(test instance)" in the window title. `Services/AppPaths` owns every path of the app's own files (settings, crash log, drafts, default backups) — never rebuild `%LocalAppData%\NoteApp` by hand, or a test instance writes into the real one's folder. `NoteDbContext` is registered with `AddDbContextFactory`; repositories take `IDbContextFactory<NoteDbContext>` and open one short-lived context per operation (everything is resolved from the root provider, so a scoped context would live as long as the app). Unhandled dispatcher exceptions are appended to `%LocalAppData%\NoteApp\crash.log` and shown in a message box instead of killing the app.

### Key Patterns

- **Result<T, AppError> monad** instead of exceptions for control flow. All repository/service methods return `Result`. Use `Match`, `Bind`, `Map` for composition; `TryGet(out value, out error)` is the imperative escape hatch for early returns — never cast to `.Success`/`.Failure`.
- **Option<T> monad** instead of nulls.
- **Immutable domain records** with `with` expressions for updates (e.g., `note with { Title = newTitle }`).
- **Value objects** with private constructors and factory methods returning `Result` (NoteTitle, TagName, LinkUrl, NoteId).
- **Sealed discriminated unions** for note block types: `NoteBlock.Text | NoteBlock.File | NoteBlock.Link | NoteBlock.Checklist | NoteBlock.Secret | NoteBlock.Code` — defined in `Domain/Models/NoteContent.cs` (filename doesn't match type name). `Match` takes one delegate per case with no default, so adding a case makes the compiler point at every place that has to handle it.
- **Checklist items live in one JSON column** — `NoteBlock.Checklist(IReadOnlyList<ChecklistItem>)` ↔ `NoteBlocks.ChecklistJson`, serialized by `Services/ChecklistJson.cs` (short keys `t`/`d`, `d` omitted when false, unreadable content yields an empty checklist). The same string goes inside the encrypted blob (`BlockDto.ChecklistJson`), so there is one item format either way. Not a child table: a save already replaces every block of a note wholesale. The block also fills `PlainText` with its item texts, which is why search and the list preview need no special case — and why the preview projection in `SearchSummariesAsync` takes the first Text **or** Checklist block (same `Where` on both sub-queries).
- **Code blocks** — `NoteBlock.Code(Content)` has no column of its own: its text is stored in `NoteBlocks.PlainText` (and `BlockDto.PlainText`), which is exactly the searchable column — no migration, `BlockType.Code = 5`. The editor is a plain Consolas `TextBox` (`AcceptsTab`, no wrap, no link handlers), so nothing is ever linkified; its copy button goes through `SensitiveClipboard` in an encrypted note. Exports: `DocCode` — one shaded Consolas paragraph per line in Word (tabs as `w:tab`), a grey box in PDF, a fence longer than any backtick run in Markdown.
- **Secret blocks** — `NoteBlock.Secret(Label, UserName, Password, Url)` ↔ `NoteBlocks.SecretJson` (`Services/SecretJson.cs`, keys `l/u/p/w`, empty fields left out; the same string in `BlockDto.SecretJson` inside encrypted blobs), migration `AddSecretBlock`. `PlainText` = label + user name + address, **never the password** — so search finds a secret and nothing else leaks; exports get a `SecretExportBlock` without the password (`DocSecret.Fields` prints a placeholder), and `CanKeepDraft` is false while a secret is in the note. The password is a MaterialDesign `RevealPasswordBox` bound through `PasswordBoxAssist.Password`. Copies go through `Services/SensitiveClipboard`: the Win32 opt-out formats (`ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory`/`CanUploadToCloudClipboard` = DWORD 0, as a `MemoryStream`), then a wipe after 30 s only if `GetClipboardSequenceNumber` has not moved (i.e. nothing was copied since) — and on exit. `NoteEditorView.OnCopying` (`DataObject.AddCopyingHandler` on the view) applies the same to Ctrl+C/X in an encrypted note or a secret's fields. Checked against the real clipboard in a probe (formats present, wipe, a later copy left alone).
- **`PlainText` next to rich text** — `NoteBlock.Text(RichText, PlainText)`: `RichText` is a Base64 XamlPackage (not searchable), so the editor also writes the plain text (`NoteEditorView.SyncBlock`) and the `NoteBlocks.PlainText` column drives search and the list preview (`Services/RichTextPreview.cs`). Rows saved before the column exists have `PlainText = NULL` and fall back to decoding the rich payload.
- **`NoteSummary` read model** (`Domain/Models/NoteSummary.cs`) for the note list: `INoteRepository.SearchSummariesAsync` projects `Data/Queries/NoteSummaryRow` (no block payloads, no `FileData`), `NoteService.SearchAsync` turns rows into summaries with a precomputed `Preview`. `NoteListViewModel` only holds summaries; `MainViewModel` loads the full `Note` by id when one is opened.
- **Unsaved-changes guard** — `NoteEditorViewModel.IsDirty` is set at the source of each change (its own `Title`/`IsEncrypted`, `Blocks` and `SelectedTags` collection changes, any `BlockViewModel` property **except** `RichTextContent`/`PlainTextContent`, which `NoteEditorView.SyncBlock` writes), and cleared by `RefreshAfterSave`. Rich text is invisible to the view model until a sync, so the view calls `MarkDirty()` from `RichTextBox.TextChanged` — with `WithoutDirtyTracking(...)` bracketing every write the app makes itself (loading a block, search highlights), otherwise opening the search bar would mark the note edited. Do **not** replace this with a snapshot comparison: `TextRange.Save(XamlPackage)` gives no byte-identical guarantee for the same document. Every exit goes through `MainViewModel.ConfirmLeaveEditorAsync()` (open another note, New note, Cancel, `MainWindow.OnClosing`); it re-runs `SaveCommand` for "Yes" and keeps the editor open when the save fails validation (`IsDirty` stays true). Deleting the open note closes its editor without prompting (`NoteListViewModel.NoteDeleted`).
- **A search follows the note it opened** — `MainViewModel.OnEditNoteRequested` passes `NoteListViewModel.SearchText` as `NoteEditorViewModel.SearchTerm`; `NoteEditorView.ShowSearchTermIfFound` (from `OnRichTextBoxLoaded`, blocks load top to bottom) opens the find bar of the first Text block containing it, one `Loaded` pass later so the bar has registered, **without** taking the focus (the list keeps it for the arrow keys). Checklist-only matches open nothing: there is no find bar there.
- **Drag and drop** — files from Explorer: the `NoteEditorView` root handles `PreviewDragOver`/`PreviewDrop` for `DataFormats.FileDrop` (tunnelling, so a RichTextBox never receives them) → `NoteEditorViewModel.AddFileBlocks`. Blocks: the grip in each card header starts `DragDrop.DoDragDrop` with the `BlockViewModel`; each card's `PreviewDrop` → `DropBlock` → `MoveBlock`. **`DropBlock` calls `SyncAllRichTextBoxes()` before moving**: a move rebuilds the card and its RichTextBox reloads from the block, so unsynced typing would be lost (a UI test pins this; the Move Up/Down buttons are safe only because clicking them blurs the box). `DropBlock`/`DropFiles` are `internal` for the UI tests (`InternalsVisibleTo`).
- **Pinned notes** — `NoteEntity.IsPinned` (migration `AddNotePinned`), carried as `NoteSummaryRow`/`NoteSummary.IsPinned`; the domain `Note` does not know it, so `UpdateAsync` never touches it and a save keeps the pin. `NoteRepository.SetPinnedAsync` writes only that column (`ExecuteUpdateAsync`) — `UpdatedAt` stays, pinning is not an edit. `NoteListViewModel.ApplySort` orders pinned first, then by the chosen sort; `TogglePin` replaces the row in place instead of reloading.
- **Checklist view state** — `BlockViewModel.HideDone` is excluded from dirty tracking (`OnBlockPropertyChanged`) and never stored; `HasDone` is raised with `ChecklistSummary`. `NoteEditorViewModel.MoveChecklistItem` hops over hidden done rows. Alt+arrow arrives as `Key.System` with the arrow in `SystemKey` (`NoteEditorView.ChecklistMoveOffset`); the moved row is rebuilt, so the focus and caret are restored one `Loaded` pass later.
- **Editor zoom** — `MainViewModel.EditorZoom` (0.5–2.5, steps of 0.1, persisted as `AppSettings.EditorZoom`) scales the `BlocksList` ItemsControl through a `LayoutTransform` bound to the Window's DataContext. Ctrl+wheel is caught by `NoteEditorView.OnEditorPreviewMouseWheel` (tunnelling, before the RichTextBox forwards the wheel to the scroll); Ctrl+Plus/Minus/0 are KeyBindings. **`SettingsViewModel.PersistSettings` saves `Current with { …its fields… }`**, never a new record: rebuilding from the form reset every setting it does not show (the zoom).
- **Keyboard shortcuts live in one place** — `MainWindow.xaml` `<Window.InputBindings>`: `Ctrl+N` → `CreateNoteCommand`, `Ctrl+S` → `MainViewModel.SaveCurrentEditorCommand`, `Esc` → `DismissCommand` (Settings dialog first, then focus mode, else the editor via the guard), `F11` → `ToggleFocusModeCommand` (only with an editor open; `MainWindow.ApplyFocusMode` zeroes the named rail/middle/splitter columns and restores the user's splitter width; `OnCurrentEditorChanged(null)` leaves it), `Ctrl+F` → the `FocusSearchCommand` RoutedCommand handled in `MainWindow.OnFocusSearch` (focus is a view concern): it walks up from `Keyboard.FocusedElement` to the nearest element whose `Tag` is a Text `BlockViewModel` → `NoteEditorView.OpenSearch(blockId)`, otherwise navigates to Notes and calls `NoteListView.FocusSearchBox()` on the next `Loaded` dispatcher pass (the middle pane may have just swapped). All three view-model commands have `CanExecute = !IsSettingsOpen` (`NotifyCanExecuteChangedFor` on `_isSettingsOpen`/`_currentEditor`), so nothing acts underneath the Settings overlay. `Ctrl+B/I/U` are native `RichTextBox` behaviour — do not rebind them.
- **Soft delete behind a global query filter** — `NoteEntity.DeletedAt`; `NoteDbContext.OnModelCreating` adds `HasQueryFilter(n => n.DeletedAt == null)`, so trashed notes are invisible to every query (list, open, update, encrypted payload) without any path having to remember the rule. Only the trash operations lift it with `IgnoreQueryFilters()`: `NoteRepository.RestoreAsync` / `PurgeAsync` / `PurgeAllDeletedAsync` and `SearchSummariesAsync(deletedOnly: true)`. Never use `FindAsync` on `Notes` — query filters do not apply to `Find`. `NoteSummary.DeletedAt`/`IsDeleted` only ever come back set from the trash query. `NoteListViewModel.IsTrashView` drives the view; a trashed row never opens the editor (`OnSelectedNoteChanged` checks `IsDeleted`, because saving it would resurrect it). `DeleteNote` asks nothing and raises `ShowUndoableMessage` (snackbar UNDO, 6 s, wired in `MainViewModel`); the `ConfirmNoteDeletion` setting guards only `PurgeNote` / `EmptyTrash`. The editor header's trash button binds to `MainViewModel.DeleteOpenNoteCommand` (via `RelativeSource AncestorType=Window`), which routes through `NoteListViewModel.DeleteNoteCommand` so both entry points share UNDO and the editor close.
- **Pure mapper functions** in `Services/Mapping/NoteMapper.cs` converting between EF entities and domain models.
- **MVVM** with `[ObservableProperty]` and `[RelayCommand]` source generators from CommunityToolkit.Mvvm.
- **TagFilterItem wrapper** in `NoteListViewModel.cs` — wraps `Tag` with observable `IsSelected` for tag filter UI state. `AllTags` is `ObservableCollection<TagFilterItem>`, not raw `Tag`.
- **Three-pane shell** in `MainWindow.xaml`: 64px navy icon rail (always `#20283D`, both themes) · `MiddlePaneContent` `ContentControl` that swaps between `NoteListViewModel` and `TagManagerViewModel` · `CurrentEditor` `ContentControl` for the active editor or empty-state; Settings is hosted in `materialDesign:DialogHost` (`RootDialog`) as a modal overlay, not a separate pane. Help is a separate **non-modal** `Views/HelpWindow` (static XAML + the shortcut table in its code-behind), single instance kept by `MainViewModel.ShowHelp` (`F1`, rail `?`); when a shortcut or feature changes, update `HelpWindow` alongside README.
- **Comfortable single-column note list** in `NoteListView.xaml`: a `ListBox` with card-style rows showing title + `Preview` snippet + tag chips + date. Under a date sort the rows are grouped (`ViewModels/NoteGroups`, pure: Pinned / Today / Yesterday / Previous 7 days / Previous 30 days / "August 2026", local days from UTC dates) — `NoteListViewModel.ApplyGrouping` puts a `PropertyGroupDescription` on the collection's default view after every sort; `VirtualizingPanel.IsVirtualizingWhenGrouping` keeps the list virtualized. The old card/DataGrid toggle was removed. Tag chips take their tag's `TagColor` (`Domain/ValueObjects/TagColor`, stored by name in `Tags.Color`, migration `AddTagColor`; NULL or unknown = Violet, the old colour) through `TagColorBrushConverter` and `Theme/TagPalette` — static pastel/dark-text pairs intentionally legible on both light and dark card surfaces, so they do not follow the theme. The colour is picked in the Tags page's Edit dialog; a selected filter chip stays solid violet. The type filter (All/Text/File/Link) is a second `ListBox` styled as MD3 filter chips (`FilterChipItemStyle`) whose `SelectedItem` binds `SelectedTypeFilter`; the reload happens in `OnSelectedTypeFilterChanged` (there is no select command), and `HasActiveFilters` drives the single "clear" button next to the search field.
- **Editor rich text never scrolls itself** — the `RichTextBox` has `VerticalScrollBarVisibility=Disabled` and grows with its content; only `BlocksScrollViewer` scrolls, and `OnRichTextBoxPreviewMouseWheel` forwards the wheel to it (a nested ScrollViewer would otherwise swallow it). Scrollbars app-wide use `MaterialDesignScrollBarMinimal` (implicit style in `App.xaml`).
- **Stored rich text carries the theme's text colour** — `TextRange.Save` bakes the inherited `Foreground` into the XamlPackage, so `DeserializeIntoRichTextBox` calls `ClearForeground` on load; without it a note written in dark mode is white-on-white in the light theme. The editor has no text-colour feature, so stripping every `Foreground` is safe.
- **Rich formatting beyond B/I/U lives in plain properties** (`Services/RichTextFormat.cs`), since a XamlPackage keeps nothing else — no styles, no tags: a heading is a top-level `Paragraph` with its **own** `FontSize` of 26/21/17 **and** bold (a loaded paragraph always carries the document's size locally, hence exact sizes), the highlighter is `Background` = the translucent `RichTextFormat.Highlighter` (on a run or a span — `IsHighlighted` walks up; pasted backgrounds of other colours are not highlights), inline code is the Consolas family, strikethrough a decoration kept alongside underline (`ToggleDecoration`). `RichTextDocument.Extract` reads them into `DocParagraph.HeadingLevel` / `DocText.IsStrike/IsHighlight/IsCode` and each exporter renders them (Markdown: the headings start at `##` under the title's `#`, `~~`, `<mark>`, backtick spans fenced longer than any backtick run inside). **The find bar paints with the same `Background`**: `PerformSearch` remembers the marks under each match (`_marksUnderMatches`) and `ClearHighlights` puts them back; toggling the highlighter while the bar is open goes through `WithSearchPaused`. Markdown line starters (`Services/LineShortcuts.cs`, pure) run deferred from `OnRichTextChanged` like the linkify, only on a top-level paragraph whose text up to the caret is exactly the starter, as one undo step; `[] ` calls `NoteEditorViewModel.SplitIntoChecklist` (checklist below the block, the following lines in a new text block, an emptied block removed). Enter at the end of a heading resets the new line to body text (WPF copies paragraph properties). No Ctrl+Alt shortcuts: AltGr is Ctrl+Alt on AZERTY. Word's `w:rPr` children are written through `WordExportService.Sorted` (schema order) and a test runs `OpenXmlValidator` over every element kind.
- **Clickable links** — `Services/TextLinks.cs` (pure, unit-tested) finds web addresses (`http(s)://`, `www.`) and only ever yields a `LinkUrl`, so nothing but HTTP/HTTPS reaches `Services/LinkLauncher.Open(LinkUrl)` (a pasted `file:` hyperlink never runs). In a text block `Services/RichTextLinks.Linkify` works **per paragraph, over the text of all its Runs** (a `CharMap` of one position per character; pasted links, line breaks and images read as spaces) — WPF splits Runs for its own reasons (paste, formatting, search highlights, `xml:lang`), and a per-Run search linked addresses only up to the split. Automatic links that no longer match an address exactly are unwrapped and linked again (this repaired notes cut that way), with the selection kept as character indices across the unwrap. It wraps them into `Hyperlink`s **without** `NavigateUri` — their text is their target, so fixing a typo fixes the link; a pasted link keeps its own target. It runs on load, in `SyncBlock`, after a paste, and deferred (Background) from `OnRichTextChanged` when the change inserted whitespace — never on `UndoAction.Undo/Redo`, or undoing a link would bring it straight back. Do not trigger it from `PreviewKeyDown`: the space arrives later as `WM_CHAR`, the link then lands before it and Ctrl+Z undoes them in the wrong order. The document stays `IsDocumentEnabled=false` (WPF's own Hyperlink click logic stays out). In a text block a **plain click opens** a link, on the button's release (`OnRichTextPreviewMouseLeftButtonUp`: no drag, empty selection, same link), and Alt+Click places the caret to edit; `OnLinkPreviewMouseLeftButtonDown` also handles `Ctrl+Click`, the only click that opens in the checklist / link-block TextBoxes, for the RichTextBox (`GetPositionFromPoint` lands inside the Run of the hit character) and for checklist / link-block TextBoxes (`GetCharacterIndexFromPoint`); the same `LinkAt` drives the hand cursor (`UpdateLinkCursor` from `PreviewMouseMove`, and from the editor's `PreviewKeyDown/Up` on Ctrl/Alt so a still mouse updates too; a hand without modifier in a text block, only with Ctrl in a TextBox). Checked with the real mouse on a test instance: hand, tooltip, Alt+Click, click → browser — `ForceCursor`, or the RichTextBox puts its I-beam back. Exports resolve each Hyperlink with the same `RichTextLinks.Target` into `DocText.Link`, and checklist items are cut around their addresses by `DocTextLinks.Split`, so Word and PDF get real links wherever the editor shows one.
- **Modern Violet MD3 theme** in `Theme/ModernViolet.xaml`: static brushes for the rail (`RailBackgroundBrush`, `RailForegroundBrush`, `RailSelectedBrush`), accent (`AccentBrush` `#6C79FF`), and tag chips (`TagChipBackground/Foreground/Border`), plus `CornerRadius` tokens (`CardCornerRadius`, `ControlCornerRadius`). All other surfaces use MDIX `{DynamicResource MaterialDesign*}` brushes and auto-switch on dark-mode toggle.

### Note Model

Notes contain ordered `NoteBlock` items (multi-block). Each block is Text (rich text), File (binary stored as VARBINARY(MAX)), or Link (validated URL). Block ordering uses `SortOrder`. Encrypted notes serialize blocks to JSON, encrypt with AES-GCM + PBKDF2, store in `EncryptedContent` column, and clear plaintext blocks from storage.

### Cross-Layer Change Coordination

When modifying note structure or block types, update across all layers:
1. `Domain/Models/Note.cs` + `Domain/Models/NoteContent.cs` (`Match` + `BlockType` + a `Has*` flag) (+ `NoteSummary.cs` and `NoteSummaryRow.cs` if the list shows it, + `NoteTypeFilter.cs` for a filter chip)
2. `Data/Entities/NoteBlockEntity.cs` + EF configuration
3. `Services/Mapping/NoteMapper.cs`
4. `Data/Repositories/NoteRepository.cs` (+ the `NoteSummaryRow` projection in `SearchSummariesAsync`)
5. `Services/EncryptionService.cs` (if it affects serialization — the `BlockDto` JSON inside encrypted notes)
6. `ViewModels/NoteEditorViewModel.cs` + `Views/NoteEditorView.xaml(.cs)` + `Views/BlockTemplateSelector.cs` (one `DataTemplate` per kind), and the dirty tracking if the block holds a collection (`Track`/`Untrack`)
6b. `Services/Export/DocumentModel.cs` (an `ExportBlock` + a `DocElement`), `RichTextDocument.Extract`, then both renderers (`WordExportService`, `PdfExportService`) — a block missing from one of them is silently dropped from that export
7. Add EF migration if schema changed
8. `tests/NoteApp.Tests` — mapper round-trip and encryption round-trip tests cover every block field

### Database Backup

`BackupService` exports a SQL Server BACPAC via DacFx, then packages it into a password-protected AES-256 zip (SharpZipLib). Triggered from `SettingsViewModel.BackupAsync()`. Output: `NoteApp_<timestamp>.zip` in the configured backup folder (default `AppSettings.DefaultBackupFolderPath`). Intermediate `.bacpac` is deleted after zipping. Returns `Result<string, AppError>`.

**Automatic backup** — `AppSettings.AutoBackup` (Off/Daily/Weekly) + `KeepBackups` (0 = all). `Services/BackupSchedule` (pure) derives everything from the folder names `NoteApp_yyyy-MM-dd_HHmmss` — no "last backup" state is stored, and manual backups count. `AutoBackupService.RunIfDueAsync` is called by `MainViewModel`'s `_backupTimer` (10 s after startup, then hourly) and prunes with `BackupService.Prune`, which deletes only folders that hold nothing but their own `<name>.zip`. The schedule combo boxes persist on change (they sit far from "Save settings").

### Drafts of unsaved changes

`Services/DraftStore` keeps `Drafts\<key>.json` in `AppPaths.DataFolder` (written through a `.tmp` + move). `MainViewModel._draftTimer` (20 s) saves `NoteEditorViewModel.CaptureDraft()` while the editor is dirty — **never for an encrypted note, nor one holding a secret** (`CanKeepDraft`; ticking Encrypt deletes the draft instead), the draft is plain JSON. `CaptureDraft` raises `SnapshotRequested`, which syncs the RichTextBoxes **without linkify** (a timer can fire mid-address). Key = the note id, or `NewNoteDraftKey` for a note never saved — `DropDraft` deletes both on save, on "No" in the leave guard and when the note is deleted. At startup (`ApplicationIdle`) `OfferDraftsLeftBehind` asks per draft, newest first; Yes → `RestoreDraftAsync` (into its note, or a new one if that note is gone or now encrypted), one per start. End-to-end checked on a test instance (UIA; MessageBox buttons are Win32 `Button`s in the raw view — click them with `BM_CLICK`).

### Automatic lock of encrypted notes

`Services/IdleLock.cs` holds the rule and takes the clock as a parameter (so it is unit-tested without waiting): armed while the editor holds a **stored** encrypted note, `Timeout` of zero means "Never". `MainViewModel.RearmEncryptedNoteLock()` re-reads `AppSettings.LockEncryptedNotesAfterMinutes` and arms/disarms on every change of what the editor holds (open, save, close, delete) and when Settings closes; a 15 s `DispatcherTimer` polls `HasExpired` instead of restarting a timer per keystroke. `MainWindow` forwards `PreviewKeyDown`/`PreviewMouseDown`/`PreviewMouseWheel` with `handledEventsToo: true` to `NotifyActivity()`, so input a control consumes still counts. On expiry a dirty note is **saved first** (its password is still in memory, so it stays encrypted) and only then closed; if the save fails validation the editor stays open with its error and the countdown is reset rather than retried every tick. The same `LockEncryptedNoteAsync` runs at once, whatever the delay, from `LockForAbsenceAsync` — `App.xaml.cs` hooks `SystemEvents.SessionSwitch` (SessionLock, Console/RemoteDisconnect) and `PowerModeChanged` (Suspend), marshals to the dispatcher, and unhooks them in `OnExit` (static events); `AppSettings.LockEncryptedNotesWhenWindowsLocks` (default on) turns it off.

Settings live in `%LocalAppData%\NoteApp\settings.json` (`AppSettingsService`). The backup password is stored DPAPI-protected for the current Windows user (`BackupPasswordProtected`); a legacy clear-text `BackupPassword` field is still read and upgraded on the next save.
